# Release Management

## Best practices
- Small incremental changes
- Automation

## Deployment strategies

Recreate:
- down time
- shutdown V1-> rollout V2

Canary:
- rollout V2 to a subset of instances, test success->V2 rollout to all instances
- fast
- zero downtime
- no extra infrastructure

A/B testing
- used when you want to see if users like the new feature
- V2 (with new feature) rolled out to subset of users, success-> V2 rollout to all users OR we go back to V1


Rolling
- V2 rolled out to a percentage of instances, V2 rolled out to the rest of instances (example 5%)
- slow
- zero downtime
- needs a lot of automation and additional setup
- no extra infrastructure
- minimizes impart to users (in case of failure)
- needs backward compatibility

Rolling with additional batch
- additional batch of new instances V2, V2 gradually rolled out to the instances batch by batch (ex 5% at time)
- same as rolling deployment except for: needs extra infrastructure, ZERO reduction in number of instances handling user requests

Blue Green
- V1 is live, create parallel env with V2, switch all traffic to V2, remove V1
- instant
- zero downtime
- easy rollback
- needs extra infrastructure
- zero reduction in available capacity
- needs backward compatibility
