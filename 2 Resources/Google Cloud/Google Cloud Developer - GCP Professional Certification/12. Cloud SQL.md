Fully managed relational database service.

- supports mysql, postgreSQL and sql server
- regional service providing high availability (99.95%)
- lot of data storage
- automatic encryption, maintenance and updates


### Use Cloud Spanner instead of Cloud SQL if:
- you have huge volumes of data (TBs) OR
- infinite scaling (TBs) OR
- global database (across multiple regions) OR
- higher availability (99.999%)

## Cloud SQL Auth Proxy

Simplifies connection management and ensures secure connection (HTTPS) between clients and Cloud SQL. Certificates will be configured automatically. Need to install Proxy Client on the client machine. Works both with public and private IP addresses. Automatically supported on some GCP services. Cloud SQL Client role is recommended.


## High availability

- create HA config, you can choose primary and secondary zones within a region
- zonal failure - switch to other instance

## Read Replica

Increases scalability of Cloud SQL instance by offloading read worklaods.


## Private Service Connection

Allows your services to communicate exclusively by using internal IP addresses.
For example VPC and network owned by Google, VM in VPC to Cloud SQL using private address.


## Serverless VPC Access

Allows Cloud Functions, Cloud run services and App Engine standard environment apps to access resources in a VPC network using those resources' private IPs. Has to be in the same region as the service. Quite expensive.

## Best practises

- Use Cloud SQL Proxy when possible
- Use connection pooling and exponential backoff
- Keep transactions short and small
- Use internal IP as much as possible
- Understand scalability
	- Enable HA config for high availability 
	- Read replicas help you off load read workloads (reporting, analytics etc.)
