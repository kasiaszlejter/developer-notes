## Cloud Firestore

Nativemode vs datastore mode

**Native mode:**
- recommended for new mobile and web apps
- offline features

**Datastore mode:**
- recommended for new server projects
- strong consistency
- does not provide offline features and real-time updates

Regional vs multi-regional

Regional:
- data is replicated in multiple zones in the same region
- used when you want lower costs
- availability SLA: 99.99%

Multi-region:
- data is replicated in multiple regions
- used to maximize availability and durability 
- can withstand loss of a complete region
- availability SLA: 99.999%

## Best practices
- document store with flexible schema
- recommended for storing things like user profiles
- design keys and indexes carefully
- create db in the region that is nearest to your users and compute resources
- prefer batch operations
- remember firestore soft limits: 1 write per second per document, 1 milion concurrent connections per database, exceeding these limits might affect performance
- gradually ramp up traffic to a new collection "500/50/5" rule
	- start with max 500 operations per second
	- increase by 50% every 5 minutes



## Cloud BigTable

Designed for huge volumes of analytical and operational data

- wide column, no sql database
- handle millions of read/write TPS
- not serverless
- cannot export data using cloud console or gcloud
- use cases; IOT streams, graph data and real time analytics, financial data
- key/value store
